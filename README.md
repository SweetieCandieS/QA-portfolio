# QA-portfolio — Любушкина Софья

Junior QA Engineer, ищу позицию в ручном тестировании с перспективой перехода в QA Automation.

В этом репозитории собраны примеры моей практической работы: тест-документация, баг-репорты и автотесты, выполненные в рамках стажировки и обучения.

## 💼 Опыт

**QA Engineer (стажировка)** · [ooon.ai](https://ooon.ai/) · Сентябрь 2026 — по настоящее время

Стартап, AI-продукт для бизнеса (чат-бот с базой знаний для партнёров). Тестирование в команде из 4 стажёров-тестировщиков. Тест-дизайн, написание тест-кейсов, оформление баг-репортов, взаимодействие с командой разработки.

Основные функции ИИ-ассистента:

1) консультирование клиентов по доступным услугам;
2) предоставление информации о стоимости услуг;
3) подбор врача/мастера с учётом запроса клиента;
4) проверка доступных временных слотов;
5) запись клиентов на приём;
6) создание и синхронизация записей с календарём.

В рамках тестирования проверялись корректность ответов ассистента, обработка пользовательских запросов, логика записи на приём, соответствие выбранных клиентом параметров созданной записи и взаимодействие с календарём.

## 📁 Структура репозитория

### [`test-documentation/`](./test-documentation)
Тест-кейсы и чек-листы.
- `checklist-listboxer.md` — тренировочное приложение ListBoxer (создание алфавитно-цифровых списков в трёх режимах, фильтрация, сортировка, сохранение в файл).
- `checklist-organizer.md` — панель редактирования задачи в веб-органайзере (клиенты → проекты → задачи), составлен по спецификации и дизайн-макетам без готовой сборки приложения.

### [`bug-reports/`](./bug-reports)
Баг-репорты по нескольким направлениям:
- [`knowledge-base/`](./bug-reports/knowledge-base) — тестирование раздела «База знаний» AI-бота **ooon.ai** в рамках текущей стажировки: баг-репорты со скриншотами.
- [`training-projects/`](./bug-reports/training-projects) — баг-репорты из учебных проектов курса (UI, функциональные, cross-browser, security).

### [`SQL/`](./SQL)
9 SQL-запросов (MySQL) на учебной базе данных сотрудников — JOIN (включая эмуляцию FULL JOIN через UNION и тройной JOIN с группировкой), подзапросы, CASE WHEN, обработка NULL (IFNULL), составные условия в HAVING, а также два примера отладки нерабочих запросов («было → стало»). Для каждого — пояснение, что он проверяет и зачем это нужно в тестировании.

### [`automation/`](./automation)
Автотесты на Python + Selenium, выполнены в рамках курса по автоматизации тестирования.

4 теста: заполнение формы регистрации с загрузкой файла, работа с JS-алертами и вкладками браузера (demo.automationtesting.in), полный сценарий в CRM — логин, создание задачи, проверка статуса и массовое обновление, удаление задачи (demo EspoCRM), добавление товаров в корзину с проверкой их количества (SauceDemo). 

Список тестов и инструкция по запуску — в [README папки](automation/README.md).
