# SQL-запросы

Запросы выполнены на учебной базе данных `employees` (сотрудники, история работ, департаменты, страны, регионы) в рамках курса по SQL/MySQL. Для каждого запроса — что он проверяет и зачем это нужно тестировщику, не только сам код.

---

### Сотрудники без записей в истории работ

Находит потенциальную проблему в данных: сотрудников, у которых нет ни одной связанной записи в таблице истории работ. Полезно для проверки целостности связи `employees` → `job_history` — похожий запрос применяется, когда нужно убедиться, что все записи в одной таблице имеют ожидаемые связи в другой, а не "висят" без пары.

```sql
SELECT * FROM employees AS e
LEFT JOIN job_history AS j ON(e.employee_id = j.employee_id);
```

*(строки, где все поля `job_history` — NULL, и есть искомые "осиротевшие" записи)*

### Полное объединение стран и локаций (эмуляция FULL JOIN)

MySQL не поддерживает `FULL JOIN` напрямую — этот запрос показывает, как получить тот же результат (все строки из обеих таблиц, включая несовпадающие) через `UNION` двух односторонних JOIN'ов. Полезно знать при проверке полноты данных, когда нужно увидеть все несостыковки сразу в обе стороны, а не только с одной.

```sql
SELECT * FROM countries LEFT JOIN locations ON(countries.country_id = locations.country_id)
UNION
SELECT * FROM countries RIGHT JOIN locations ON(countries.country_id = locations.country_id)
```

### Количество локаций по странам через регионы

Джойн сразу трёх таблиц (`locations` → `countries` → `regions`) с группировкой и сортировкой по количеству. Такой запрос удобен для проверки данных на глаз: если у одной страны локаций сильно больше, чем у остальных, — это повод проверить, не баг ли это (например, задвоение записей).

```sql
SELECT l.country_id, COUNT(*) FROM locations AS l
INNER JOIN countries AS c ON(l.country_id = c.country_id)
INNER JOIN regions AS r ON(c.region_id = r.region_id)
GROUP BY l.country_id
ORDER BY COUNT(*) ASC;
```

### Сотрудники с зарплатой выше минимальной среди получающих комиссионные

Подзапрос с агрегатной функцией в `WHERE`: сначала находим минимальную зарплату среди тех, у кого есть комиссионные, затем фильтруем всех сотрудников по этому порогу. Пример того, как подзапрос используется как динамическое значение для сравнения, вместо жёстко заданного числа.

```sql
SELECT first_name, last_name, job_id FROM employees
WHERE salary > (SELECT MIN(salary) FROM employees WHERE commision IS NOT NULL);
```

### Классификация зарплаты по уровням (CASE WHEN)

Разбивает сотрудников на категории по величине зарплаты. Похожий паттерн применяется при категоризации тестовых данных или статусов — например, для группировки объектов по диапазонам значений при анализе результатов.

```sql
SELECT first_name, salary,
CASE
WHEN salary < 4500 THEN 'Low level'
WHEN salary >= 4500 AND salary < 9000 THEN 'Normal level'
WHEN salary >= 9000 THEN 'High level'
END AS salary_level
FROM employees;
```

### Обработка NULL в вычисляемом столбце (IFNULL)

Если у сотрудника нет комиссионных (`commision IS NULL`), прямое умножение `commision*salary` даст `NULL` — что может выглядеть как ошибка при чтении отчёта. `IFNULL` подставляет понятное значение вместо "пустоты". Работа с NULL — то, что часто выявляет реальные баги в проде, когда NULL появляется там, где его не ожидали.

```sql
SELECT last_name, commision, salary, IFNULL(commision*salary, 'no') AS bonus
FROM employees;
```

### Исправление нерабочих запросов

Два примера "было → стало": находим синтаксическую ошибку в исходном запросе и чиним её. Показывает не только знание синтаксиса, но и навык отладки чужого/сломанного SQL — то, с чем тестировщик сталкивается регулярно.

**Пример 1 — отсутствовали кавычки у строкового значения:**
```sql
-- Было (ошибка): job_id = AD_SUP — без кавычек MySQL ищет столбец/переменную с таким именем, а не строку
SELECT employee_id, first_name FROM employees WHERE job_id = AD_SUP;

-- Стало:
SELECT employee_id, first_name FROM employees
WHERE job_id = 'AD_SUP';
```

**Пример 2 — отсутствовали разделители между операторами и неверный порядок в ORDER BY:**
```sql
-- Было (ошибка): пропущены пробелы/переносы между FROM, WHERE, ORDER BY;
-- строковое сравнение с числом; DESC стоит перед именем столбца вместо после
SELECT * FROM employees;WHERE salary < '24000'ORDER BY DESC salary;

-- Стало:
SELECT * FROM employees
WHERE salary < 24000
ORDER BY salary DESC;
```

### Job_id с более чем 3 сотрудниками и суммой зарплат выше 25000

Группировка с двумя условиями в `HAVING` одновременно — по количеству строк в группе и по агрегированной сумме. Пример проверки "составного" условия на уже сгруппированных данных, а не на отдельных строках (для этого и нужен именно `HAVING`, а не `WHERE`).

```sql
SELECT job_id FROM employees
GROUP BY job_id
HAVING COUNT(*) > 3 AND SUM(salary) > 25000;
```
